# SecureMailScope — Data Directory

## Overview

This directory stores datasets used for training and evaluating the
ML risk scoring model. **Large datasets and model artifacts should
NOT be committed to this repository.**

## Directory Structure

```
data/
├── raw/          # Raw analysis JSON files (output from Django analysis service)
├── curated/      # Reviewed and curated analysis JSON files ready for feature extraction
├── processed/    # Training-ready CSV datasets (generated by dataset_builder.py)
├── labels/       # Manual risk labels (CSV format)
└── README.md     # This file
```

## Manual Team Responsibilities

The following steps require manual team work and cannot be automated:

### Step 1: Collect PCAP Datasets

Collect safe and legally usable PCAP datasets containing:
- **SMTP** traffic (ports 25, 587, 465)
- **IMAP** traffic (ports 143, 993)
- **POP3** traffic (ports 110, 995)

Sources may include:
- Controlled lab captures
- Publicly available test datasets
- Synthetic traffic generators

> ⚠️ **Do NOT use production email traffic or datasets containing
> real user credentials or personal information.**

### Step 2: Run PCAPs Through the Analysis Pipeline

Run each PCAP through Hardik's Django analysis service to generate
structured analysis JSON.

### Step 3: Save Structured Analysis JSON

Save the output JSON files to:

```
data/raw/           # Unmodified analysis output
data/curated/       # Reviewed files ready for ML processing
```

Filename convention: `<analysis-id>.json`

### Step 4: Review Extracted Sessions

Review the sessions and findings in each analysis file for accuracy.

### Step 5: Manually Assign Risk Labels

For each session, assign a risk label:

| Label      | Description                                    |
|------------|------------------------------------------------|
| `LOW`      | No significant security issues                 |
| `MEDIUM`   | Minor issues (e.g., PFS missing)               |
| `HIGH`     | Significant issues (e.g., deprecated TLS)      |
| `CRITICAL` | Severe issues (e.g., plaintext auth, no TLS)   |

### Step 6: Store Labels

Save labels to `data/labels/session_labels.csv` in this format:

```csv
analysis_id,session_id,risk_label
analysis-001,smtp-001,LOW
analysis-001,smtp-002,CRITICAL
analysis-001,imap-001,CRITICAL
analysis-001,pop3-001,LOW
```

### Step 7: Build the Training Dataset

```bash
python -m ml.training.dataset_builder \
    --input data/curated \
    --labels data/labels/session_labels.csv \
    --output data/processed/training_dataset.csv
```

### Step 8: Review the Generated Dataset

Inspect `data/processed/training_dataset.csv` to verify:
- Correct number of sessions
- Feature values make sense
- Labels are correctly joined
- No unexpected NaN patterns

## Training and Evaluation

After building the dataset:

```bash
# Train the model
python -m ml.training.train \
    --data data/processed/training_dataset.csv \
    --output ml/artifacts

# Evaluate the model
python -m ml.training.evaluate \
    --data data/processed/training_dataset.csv \
    --model ml/artifacts/risk_model.joblib

# Predict risk for new analysis
python -m ml.inference.predictor \
    --analysis data/curated/example.json
```

## Important Notes

- The MVP model is a **proof of concept** for hackathon demonstration.
- Do not claim the model is scientifically validated unless the team
  has collected sufficient, diverse, and correctly labeled data.
- Minimum recommended dataset size: 50+ labeled sessions across
  multiple protocols and security configurations.
